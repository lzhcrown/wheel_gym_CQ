一、训练
cd /home/bit/wheel_gym_CQ
bash scripts/train_mine.sh --max_iterations 10000 --headless

脚本自动激活项目 .venv，只训练 nezha2_mine。也可以手动运行：
source scripts/activate_train.sh
python wheel_legged_gym/scripts/train.py --task nezha2_mine --max_iterations 10000 --headless

未传入覆盖参数时使用现有方法配置：4096 个并行环境、seed=10、复杂地形
trimesh、每轮每环境采样 24 步、100000 次迭代、每 200 次迭代保存模型。
奖励、地形课程和优化器超参数继续使用该方法原有设置。
可通过 --num_envs、--seed、--max_iterations、--save_interval 覆盖对应参数。
运行时按 Ctrl+C 停止；已经写入的平均奖励 CSV 会保留。

当前网络的数据定义：
Source encoder 与门控均读取 [o(t-1), o(t)] 两帧历史，共 130 维。
门控结构为 130 -> 64 -> 3；Actor 直接读取最新帧 o(t) 的 65 维，
再拼接 4 维估计量和 16 维隐特征，总输入仍为 85 维。
辅助训练、策略采样、推理和导出共用同一套隐特征计算：各模态原型先
分别做 L2 归一化，再按门控权重混合、逐元素调制隐特征并归一化。
Target encoder 仅在辅助训练中读取执行动作前的当前特权帧 p(t)，
完整输入 375 维；is_privileged_obs=True。当前 Critic 的三帧输入
[p(t-2), p(t-1), p(t)] 仍为 1125 维，Target 取其最后 375 维。
4 维速度/高度回归监督沿用原来的下一状态 p(t+1)，与 Target 的
当前帧输入分开传递；回合终止时采用旧回合的终止状态监督。
门控和 Target 首层维度已改变，旧结构检查点不能直接恢复本版网络，
本版应从头训练；本版检查点可正常用于恢复和导出。

activate_train.sh 清除系统 ROS 的 PYTHONPATH，设置 Python 3.8 动态库目录
和当前环境独立的 gymtorch 编译缓存。新终端中需重新激活，退出用 deactivate。

二、输出与恢复
输出目录：logs/nezha2_mine/时间戳_rough-1/
只导出一个奖励 CSV：csv/Train_mean_reward.csv
CSV 三列：wall_time,step,value；保留未平滑的原始记录。
value 为最近最多 100 个已结束回合的平均累计回报，step 为从 0 开始的
训练迭代号。尚无回合结束时，该指标没有数据行。
CSV 在训练期间实时写入。TensorBoard、模型检查点、实际配置和源码快照
也保存在本次运行目录，用于恢复和核对。

从本方法最新检查点恢复：
bash scripts/train_mine.sh --resume --max_iterations 10000 --headless
恢复时 max_iterations 表示本次追加的训练迭代数。
指定运行目录和检查点时增加 --load_run RUN_NAME --checkpoint ITERATION。

从已有事件文件补导平均奖励 CSV：
python wheel_legged_gym/scripts/tensorboard_data_ex.py logs/nezha2_mine/RUN_NAME

MATLAB 读取示例：
T = readtable('logs/nezha2_mine/RUN_NAME/csv/Train_mean_reward.csv');
% T.step 是训练迭代号，T.value 是平均奖励。

三、重新创建环境
cd /home/bit/wheel_gym_CQ
UV_VENV_SEED=false uv venv --cache-dir .uv-cache --python 3.8.20 .venv
uv pip install --cache-dir .uv-cache --python .venv/bin/python --index https://download.pytorch.org/whl/cu118 --index-strategy unsafe-best-match -r requirements-train-py38.lock
uv pip install --cache-dir .uv-cache --python .venv/bin/python --no-build-isolation --no-deps -e /home/bit/isaac/isaacgym/python -e .
uv pip check --cache-dir .uv-cache --python .venv/bin/python

虚拟环境与下载缓存分别使用项目内 .venv 和 .uv-cache。
依赖锁文件不包含机器相关的 editable 路径；换机器时需修改 Isaac Gym 路径。
首次导入 gymtorch 会编译本机扩展，需要系统 C++ 编译器和环境内的 ninja。

四、查看训练曲线
在新终端执行（不需停止训练）：
cd /home/bit/wheel_gym_CQ
source scripts/activate_train.sh
python -m tensorboard.main --logdir logs/mine_ablation --host 127.0.0.1 --port 6008 --reload_interval 10
本机浏览器打开 http://127.0.0.1:6008/，在 Scalars / Time Series 中选择
Train/mean_reward，横轴 Step 表示训练迭代。勾选不同 Runs 可叠加对比。
查看主方法的独立训练时，将 logdir 换为 logs/nezha2_mine；查看所有训练用 logs。
端口占用时可同时修改启动命令和浏览器地址中的端口。

若启动后浏览器请求报错：
TypeError: MessageToJson() got an unexpected keyword argument 'including_default_value_fields'
这是 TensorBoard 2.14 与 protobuf 5 的 API 不兼容。项目锁文件固定 protobuf
4.25.9；已有环境可在项目根目录执行以下命令修复：
uv pip install --cache-dir .uv-cache --python .venv/bin/python --no-deps 'protobuf==4.25.9'
uv pip check --cache-dir .uv-cache --python .venv/bin/python
随后只在运行 TensorBoard 的终端按 Ctrl+C，再执行上面的启动命令，刷新网页。
Python 3.8 的弃用警告、TensorFlow installation not found 提示与此接口报错不同；
当前 PyTorch 事件文件的奖励曲线不需要安装 TensorFlow。
